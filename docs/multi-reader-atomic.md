# Where a regular-register construction loses atomicity

This reconstruction has a negative atomicity result and a separate positive completion result. Two Lean-checked executions show that the normalized Figure 1 construction can return a newer write and then an older write to nonoverlapping reads. Completing every operation does not fix the second execution. This is not a verified atomic-register implementation.

A regular register promises that a read sees the last preceding write or a write overlapping that read. It permits one read to see a new value and a later read to see the old value while the same write remains active. Figure 1 uses two payload buffers, a level register, and per-reader writer, reader and forwarding tokens (WC, RC and FC). All are regular, including FC. Every operand read and subsequent write has its own interval; comparisons are not atomic snapshots.

The writer samples RC and FC for each reader, selects a token different from both samples and stores it in WC. It writes level 1, the first buffer, level 2, the second buffer, and finally level 0. A reader copies its WC token into RC, saves the first buffer, scans FC/WC pairs for a forwarding notice, and samples the level and its RC/WC pair. These observations decide whether to read the second buffer or use the saved first sample. On the forwarding branch, its required RC read and FC write finish before the high-level response.

Two source corrections are explicit. The printed counter declaration has values 1 through 3 but initializes WC to 0. The model uses three abstract tokens represented by 0, 1 and 2, preserving the initial equalities and the existence of a token different from two observations. The dependency graph in the proof says Buff2 where Figure 1 and the surrounding argument select saved Buff1. The reconstruction follows saved Buff1. Neither correction proves the construction correct.

The first certificate is a 144-step, one-reader execution in the original model, which permits either operand order. Consecutive reads return source 3 and source 2. A separately named model restricts the writer to RC-before-FC. Its 200-input counterexample uses two readers, evaluates every operand pair left first, and ends with all seven calls and every primitive completed. W3 sees the new value of reader 0's pending FC write; reader 1 later sees the old value during that same FC write. Those observations are legal for a regular register. Two consecutive reads by reader 1 then return sources 3 and 2. Both certificates refute API and source-lifted no-reversal criteria. The result concerns this reviewed reconstruction and regular-register contract; it is not a theorem that atomic registers cannot be constructed.

API provenance remains proved: a returned value and ghost index belong to initialization or an already invoked writer. Invocation-rooted replay also preserves the actual supplying witnesses and instruction sequence. These facts do not establish freshness, a common atomic order, or the protected general criterion bridge. The operational histories use explicit endpoints; no equivalence with every abstract partial order in the paper is claimed.

Own completion is proved separately for both original and restricted models. A writer invokes at most `3n+5` primitives, and a reader at most `2n+8`, for arbitrary payloads and every positive finite reader count. A finite program measure decreases as a process takes its own actions; other processes need no fairness. Eventual completion retains both terminating-primitives and continued-own-scheduling premises. The latter applies even while a primitive is pending, so in this endpoint model it already demands progress out of waiting phases. The budgets count primitive invocations, not endpoint transitions or elapsed time. They cannot turn incorrect return ordering into atomicity.

No stronger FC assumption, repair, positive common-order/whole-run theorem, stronger source provenance, safe-bit composition, later variant or lower bound is claimed. CSLib's labelled traces fit the endpoint model; regular histories and invocation accounting remain local. This paper's regular registers differ from the raw buffers and atomic controls of Concurrent Reading While Writing. There is no composition theorem between the two developments.
