# Reading an intact value while a writer changes it

Solution 3 lets one writer update a large value while any positive finite number of readers obtain intact, recent values. The checked construction uses two shared buffers plus one reserved buffer per reader. Raw buffer operations may overlap and return arbitrary corrupt data. Separate atomic binary controls determine which saved sample is safe to return.

A reader signals a request using a handshake bit, samples the writer flag and switch, reads the first buffer, samples those controls again, then reads the second buffer. If its request has been acknowledged, it reads its reserved copy. Otherwise it chooses between the two saved shared-buffer samples using the control observations. The second flag/switch samples precede the second buffer read. A writer marks the first buffer busy, fills it, toggles the switch and clears the flag, scans reader handshakes and makes requested copies, then fills the second buffer. After a copy it freshly reads the reader's signal before acknowledging; it does not reuse the earlier test sample.

Each shared binary read or write is a separate atomic action, including the operands within an assignment or comparison. Raw reads and writes have distinct beginnings and endings. A raw read overlapping any write may return any payload, even one never written; a disjoint read returns the last completed raw write. One writer and sequential calls per reader are assumed, with a completed initial write W0 and arbitrary private initial data. Repeated equal payloads still have different ghost write identities. Ghost identities and overlap marks cannot affect the algorithm's choices.

The integrity proof derives protection from the actual handshake and control steps. Equal handshake bits protect the reserved copy. Without acknowledgement, the scan barrier prevents a writer from reaching the second buffer too early, and the switch/flag samples rule out returning a torn first-buffer sample. Discarded samples may remain corrupt. A separate provenance invariant tracks the actual supplying write and its payload, rather than identifying a write by payload equality.

The ordering proof bounds each returned source between the writer's progress at invocation and response. Those bounds establish recency and prevent a later nonoverlapping read, even by another reader, from returning an older source. Completed reads are grouped after their source writes to construct one common order for each finite history. The witness may append a response for the sole pending writer and omits pending reads. This history extension does not show an executable continuation that finishes the writer, nor a prefix-consistent choice of orders or strong linearizability.

Completion is a separate countdown argument: readers follow a finite branch and writers scan each reader once. An interval in which a call remains busy cannot contain `16+6*n` successful own abstract actions. Unbounded successful own actions therefore force a response. Realizing that premise requires continued scheduling of that process and termination of every raw operation it invokes. Raw beginnings and endings count as abstract actions; the theorem bounds neither physical accesses nor elapsed time and needs no progress by another process.

The `n+2`-buffer necessity claim, Theorem 3's waiting terminology, garbage collection, multiple writers, physical memory implementations and general system simulation remain outside the result. Lamport's 1984 note, On a “Theorem” of Peterson, objects to Theorem 3's informal waiting claim; it is not a counterexample to this Solution 3/Theorem 2 target. CSLib supplies finite labelled traces; raw intervals and the common-history construction remain local definitions.
